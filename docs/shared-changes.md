- Approval handlers registered: `TENDER_GO_NO_GO` (flow GO_NO_GO, also the demo seed's pending requests) and `TENDER_CONVERSION` (flow TENDER_CONVERSION). Other seeded entity types (PURCHASE_*, PAYROLL_RUN, SUBCONTRACTOR_BILL) have no handler: deciding them returns NOT_FOUND until their module registers one.
- GO/NO-GO semantics: the Admin requests GO or NO-GO (NO-GO needs a reason; stored in the audit row `tender.go_nogo.request` with `approvalRequestId`). Director APPROVE applies it (GO: tender moves to Bid Preparing + GoNoGoDecision row; NO-GO: tender closes in a NO_GO stage if configured, otherwise the Lost stage with the neutral "Cancelled" result). REJECT declines the request: tender stays Under Evaluation, no decision row. A request without a stored proposal (seeded demo requests) is treated as GO.
- Conversion: `requestConversion` (Admin, `tender_conversion:SUBMIT`) -> Director approval creates Project + ProjectConversion in the decision transaction (code `SPH-<region>-NN`, region default GSTIN, plant site = tender.siteId or first site of org+region, PBG instruments re-pointed). Project manager is left empty (no project_manager role in the 2-role scope).
- Needs from schema owner (nothing required). Optional: a `payload Json?` on ApprovalRequest would replace the audit-row lookup used for the GO/NO-GO proposal and the conversion override reason.

## S3-B real data (build: dashboard + projects/subcontractors on the DB)

### Data flow (read this before touching screens)
- `SessionGate` (root layout, server) loads the Database via `getServerDb(userId)` (`src/lib/data/server/server-db.ts`) and wraps the shell in `ServerDbProvider` (`src/components/auth/server-db-provider.tsx`). `useDb()` returns that server db; the Zustand store is only the fallback when no provider exists (styleguide). `useAsOfDb()` still wraps `useDb()`.
- Persona = the signed-in user's own `db.users` row (`matchDbUserId`, id then e-mail). No stand-in persona; `ROLE_PERSONA_FALLBACK`/`resolvePersonaUserId` removed. The dev role switcher is hidden when real data is provided.
- After a server action, call `router.refresh()`: the layout re-renders and sends a fresh db. `runAction` now calls `invalidateServerDb()` (`src/lib/server/invalidate.ts`, `updateTag("server-db")`) after every committed non-VIEW write so the snapshot cache is expired immediately. **Any write that does not go through `runAction` (route handlers, jobs, scripts) must call `invalidateServerDb()` itself**, otherwise users see stale data for up to 30 s (cache life: revalidate 30 s, expire 10 min).
- The snapshot is ONE unscoped load shared by all unrestricted users (both roles). `loadDatabaseLean` falls back to the scoped `loadDatabaseForUser` for a region/project-restricted user (none exist in the 2-role version). With the PHASE67 flag off it skips: daily reports/items, site issues, attendance, payroll, payslips, site assignments, labour types, invoices, GST, purchases, stock; it always skips stored notifications and audit logs.
- Child-table queries in the tender/project/approval/party loaders now run in the same round as their parent when no scope restricts rows (`parentIn`, `isUnscoped` in `convert.ts`). `loadProjectTables` now also loads `projectStatuses` (was never loaded before; the dashboard crashed without it).
- `PHASE67` now also hides Daily work (`daily_work` nav key, `/daily-work` layout 404s). **Set `NEXT_PUBLIC_FEATURE_FINANCE_PAYROLL=false` in `.env.local` for dev/e2e**: the default is ON whenever APP_ENV is not production, which loads about 27k rows and shows the Employees/Finance/Daily work screens. `src/lib/__tests__/features.test.ts` "on under the test environment by default" assumes the flag is unset; run it with the flag unset.
- Bell: computed on read (tender deadlines within 7 days + approvals waiting for the user). No stored notifications and no "mark read" writes. `NotificationsMenu` testids: `notifications-bell`, `notifications-count`.

### Pooled DATABASE_URL on Vercel (no migration needed)
- Runtime `DATABASE_URL` = Supabase TRANSACTION pooler (port 6543): `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1`. `src/lib/server/prisma.ts` adds `connection_limit` (1 on Vercel, 8 locally) and `pool_timeout=30` only when the URL does not set them, and keeps one PrismaClient per instance (`globalThis`).
- Migrations (`prisma migrate deploy/dev`) need a non-pooled connection: set `DIRECT_URL` (session pooler port 5432 or the direct db host). `prisma/schema.prisma` is not edited here (forbidden for this task); to use it add `directUrl = env("DIRECT_URL")` to the `datasource db` block. That is a schema-file edit with no migration, but until it is added `migrate` uses `DATABASE_URL`. Until then run migrations from a shell where `DATABASE_URL` is temporarily set to the direct/session URL. `DIRECT_URL` is listed (no value) in `.env.example`.
